# 다이어그램 레시피

각 레시피는 **하나의 주장**을 한다. 주장이 없으면 그리지 않는다 —
박스에 이름만 적은 그림은 본문 문장을 다시 쓴 것이고, 독자의 시간만 쓴다.

좌표는 출발점이다. 내용에 맞춰 조정하되 **정렬 규율**(같은 층 같은 y, 라벨 공통 기준선)은 지킨다.

---

## R1 — 여정도 (필수)

**주장**: 일이 어느 지대에서 벌어지고, 경계를 몇 번 넘는가.

두 개의 가로 밴드(위=클라우드, 아래=LLM 서버)에 정거장을 **번갈아** 놓는다.
번호가 위아래를 오가는 모양 자체가 "두 번 건너간다"를 말한다.

```
viewBox="-32 0 1432 470"          왼쪽 음수 여백 = 거터 라벨 잘림 방지
거터 라벨   x=104, text-anchor=end,  y=110/131 (위) · 322/343 (아래)
밴드        x=120 w=1200,  y=76 h=78 (위) · y=288 h=78 (아래)
정거장      w=180~190 h=62,  y=84 (위) · y=296 (아래)
            x = 140 · 380 · 630 · 870 · 1120  (위·아래 번갈아)
대각 화살표  박스 모서리 → 다음 박스 모서리
화살표 라벨  중점 x, y=215 / y=232  (전부 같은 기준선)
반복 루프   상단 점선 베지어 + y=24 라벨
```

- 정거장 문구는 **동사로** 쓴다. "① 접수하고 보관", "④ 문서를 다시 쓰기".
- 각 박스 아래줄에 부연 한 마디(11.5px, `--ink-2`).
- 맨 아래 구분선 + 한 문장 주석으로 경계 규칙을 못 박는다
  (예: "원본 파일은 LLM 서버에 남지 않습니다").

**지대가 하나뿐인 앱**이면 밴드를 "사용자가 보는 것 / 뒤에서 저절로 도는 것"으로 재배정한다.

---

## R2 — 대기열 3단 (Queue 바인딩이 있을 때)

**주장**: 요청과 처리가 분리돼 있고, 결과는 되돌아오는 길로 온다.

`sequence` 형태보다 **가로 파이프라인 + 되돌아오는 점선**이 비개발자에게 잘 읽힌다.

```
[앱] --넣기--> [대기열] --꺼내기--> [소비자] --부탁--> [LLM 서버]
                                      ^                    |
                                      +---- 결과 돌려줌 ----+
[앱] <--저장--- [소비자]
```

반드시 라벨로 밝힐 것: **누가 먼저 말을 거는가.** 이 레포에서 LLM 서버는 대기열을 스스로 꺼내지
않는다(소비자가 부른다). 그림에서 화살표 방향이 그것을 말해야 한다.

되돌아오는 선은 점선 + `--mac`. 결과 파일 경로도 라벨로 적는다("결과는 클라우드가 창고에 넣는다").

---

## R3 — 상태 흐름 (오래 걸리고 재개되는 작업)

**주장**: 중단돼도 이어지는 이유는 진행 상태를 **기억이 아니라 기록에** 두었기 때문이다.

```
viewBox="0 0 1060 250"
알약 박스 h=58 rx=29,  y=70,  x=20 · 270 · 520 · 790
자기 반복 상단 베지어(같은 박스로 돌아옴) + "페이지 수만큼" 라벨
하단 띠   y=168 h=52, --cf-soft 배경 — "진행 상태는 전부 기록에 남습니다"
점선      각 박스 → 띠 (모든 상태가 기록된다는 뜻)
```

상태 이름은 코드의 문자열이 아니라 **사람 말**로 쓴다(`converting` → "변환중").
소요 시간을 아는 경우 반드시 넣는다 — "왜 잘게 나눴나"의 근거다.

---

## R4 — 방법 비교 (두 방식을 합쳐 쓸 때)

**주장**: 하나만 쓰면 각각 **다르게** 틀린다. 그래서 합쳤다.

같은 입력 하나를 위에 놓고, 아래로 갈라 3개 패널(A만 / B만 / 함께).
**같은 예시 데이터**를 써야 비교가 성립한다.

```
원본 박스   x=20 y=42 w=300 h=66   (mono 로 실제 입력 모양)
분기선      원본 중점에서 아래 → 가로 → 각 패널로 (화살촉 3개)
패널        y=158 h=150,  x=20 · 380 · 740
            실패 패널은 --rule 테두리 + --warn 으로 ✕ 와 틀린 값 강조
            채택 패널은 --mac 테두리 2px + --mac-soft 반투명 배경 + ✓
```

틀린 값은 **그 자리에서 색으로** 보여준다(예: `3,600` 이 `3,500` 으로 바뀐 것).
"부정확하다"는 설명보다 바뀐 숫자 하나가 강하다.

---

## R5 — 관문 (접근 제한이 있을 때)

**주장**: 단계 **순서**에 이유가 있다.

```
viewBox="0 0 1000 210"
관문 박스  w=200 h=56, y=60,  x=20 · 310 · 600
통과 알약  x=880 w=100 rx=28, --mac
지름길    상단 점선 베지어(2번째 관문 → 통과)
탈락      각 관문에서 아래로 --warn 화살표 + 사용자에게 보이는 문구
```

탈락 라벨은 오류 코드가 아니라 **사용자가 실제로 보는 문장**으로 쓴다
(`401` ✕ → "로그인이 필요합니다" ○).

`figcaption` 에서 순서의 이유를 밝힌다 — 왜 이 단계가 저 단계보다 앞이어야 하는가.

---

## R6 — 순서 중요도 (뒤집으면 깨지는 순서)

**주장**: 이 순서여야만 한다. 뒤집으면 복구 불가능해진다.

좌우 2패널: 왼쪽 `✓ 지금 방식`(`--mac`), 오른쪽 `✕ 순서를 뒤집으면`(`--warn`).
각 패널 안에 ①→② 두 박스, 아래에 결과 2줄 + 결론 1줄.

```
viewBox="0 0 980 260"
패널  w=430 h=86, y=44,  x=20 · 530
내부 박스 w=150 h=42, y=66,  x=+22 · +252
실패하는 쪽 박스는 stroke-dasharray="4 3"
결론 줄  y=200,  --mac / --warn, font-weight 700
```

파기·마이그레이션·롤백처럼 **되돌릴 수 없는 작업**에 쓴다.

---

## R7 — 일정 타임라인 (Cron 이 여럿일 때)

**주장**: 사람이 아무것도 안 해도 하루에 이런 일들이 저절로 일어난다.

24시간 가로축에 눈금과 사건 마커. 각 마커에 시각·역할·처리량.
`triggers.crons` 는 UTC 이므로 **KST 로 변환해서** 표시하고, 괄호로 원값을 남긴다.

## 머메이드 레인 (정본 `docs/apps/<앱>.md`)

레포 정본은 손 SVG 가 아니라 머메이드다. 표현력이 줄어드는 대신 diff 로 리뷰되고 낡은 것이 눈에 띈다.
**레시피의 주장은 그대로 두고 표현만 바꾼다.**

| 레시피 | 머메이드 대응 | 비고 |
|---|---|---|
| R1 여정도 | `flowchart LR` + 지대별 `subgraph` | 지대가 번갈아 나오면 `subgraph` 을 여러 번 연다(`CL1`·`LS1`·`CL2`…). 반복은 `-.->` 점선 |
| R2 대기열 3단 | `flowchart LR` | 되돌아오는 길을 `-.->` 로. **누가 먼저 말을 거는가**를 화살표 방향으로 |
| R3 상태 흐름 | `stateDiagram-v2` | 자기 반복은 `변환중 --> 변환중: 라벨` |
| R4 방법 비교 | **표 + 보조 `flowchart TB`** | 머메이드는 나란한 비교에 약하다. 결과 대조는 표가 정본, 그림은 갈라짐만 |
| R5 관문 | `flowchart LR` + `{"판단"}` 마름모 | 탈락은 사용자에게 보이는 문장으로 |
| R6 순서 중요도 | **`flowchart LR` 2블록** (`✓` 먼저, `✕` 나중) | 한 그림에 subgraph 2개로 넣으면 **머메이드가 좌우 순서를 뒤집는다** — 독자가 틀린 쪽을 먼저 본다. 블록을 나누면 순서가 고정된다 |
| R7 일정 타임라인 | 표 | 머메이드 `timeline` 은 렌더러 지원이 고르지 않다 |

### 머메이드 함정

- **라벨에 `(`·`)`·`:`·`,` 가 있으면 큰따옴표로 감싼다.** 안 그러면 그 그림이 통째로 안 그려진다.
  `A["펴고 글자 위치 읽기 (300dpi)"]`
- `stateDiagram-v2` 의 **상태 이름에는 공백을 쓰지 않는다.** 공백이 필요하면 `s1: 표시 이름` 형태로.
- 줄바꿈은 `<br/>`. 부연은 `<small>…</small>` 로 한 급 낮춘다.
- 표 셀 안에서 파이프(`|`)를 쓰려면 `\|` 로 이스케이프한다 — 마크다운 표가 깨진다.
- 노드 id 는 영문으로, 화면에 보이는 글자는 대괄호 안 라벨로 둔다.

---

## 안 그려야 하는 것

- **구성 요소 나열** — 표가 더 낫다. 등장인물 표를 쓸 것.
- **폴더 구조** — 비개발자에게 의미 없다.
- **박스 3개에 이름만** — 본문 문장의 재탕.
- **선택지를 서로 연결하지 않은 비교** — 무엇과 무엇을 고르는지 안 보인다. 차이를 그려야 비교다.
