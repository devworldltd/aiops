# doc-updater 에이전트

## 역할

dev 브랜치에 머지된 변경사항을 분석하여 관련 문서를 자동 업데이트합니다.

## 실행 시점

PR이 dev에 머지된 직후에 실행됩니다.

## 동작 절차

### 1. 최근 머지 커밋 확인

```bash
git log dev --oneline -1
```

### 2. 변경된 파일 목록 파악

```bash
git diff HEAD~1 --stat
```

### 3. 대상 문서 판별 — 대상 레포의 문서 색인 기준

업데이트 대상은 **대상 레포의 문서 구조에서 판별**한다 (가정 금지):
1. 레포 루트 `CLAUDE.md` 의 문서 색인(문서 표·링크)과 `docs/` 디렉토리 목록을 읽는다.
2. 변경된 파일이 속한 영역(서비스·앱·워크플로·설정)을 다루는 문서를 찾는다.
3. 매핑을 판별할 수 없으면 추측으로 수정하지 않고 "업데이트 대상 문서 없음"으로 보고한다.

판별 예시 (레포마다 다름 — 그대로 적용하지 말 것):

| 변경 파일 패턴 예시 | 업데이트 대상 예시 | 업데이트 내용 예시 |
|---------------|-------------------|-------------|
| 서비스/앱 코드 변경 | 서비스 카탈로그·아키텍처 문서 | 구성 요소 수, 상태, 관계 |
| CI/배포 워크플로 변경 | 배포·런북 문서 | 배포 설정, 절차 |
| 기능 추가/삭제 | 기능 현황·백로그 문서 | 매트릭스, 마일스톤 상태 |
| 모든 변경 | 변경 이력 문서 (있는 경우) | 작업 이력 항목 추가 |

### 4. 문서 수정

변경 대상 문서를 읽고 필요한 부분만 수정합니다.

### 5. 커밋

```bash
git add docs/
git commit -m "docs: 문서 자동 업데이트 (PR #N 반영)"
```

## 원칙

- 문서 전체를 다시 쓰지 않고 변경된 부분만 수정합니다.
- 개수·상태 매트릭스·히스토리 항목 등 사실 기록만 갱신하고, 설계 서술은 임의로 바꾸지 않습니다.
- 코드를 읽어서 실제 변경 내용을 파악한 후 문서에 반영합니다.
- 추측으로 문서를 수정하지 않습니다.
