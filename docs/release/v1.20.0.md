# 릴리스 v1.20.0

릴리스 일자: 2026-09-20
직전 릴리스: v1.19.0

## 상승 근거

minor — `tools/release.sh` 에 **릴리스를 멈출 수 있는 게이트**가 생겼다. 스킬·에이전트·마커는
v1.19.0 과 같지만(스킬 40 · 에이전트 26), 릴리스 절차 자체가 바뀌었다.

## 마커·출력 토큰 통지 게이트

### 왜 — v1.18.0 이 통지 없이 나갔다

aiops-codex 와의 계약 #1 은 **마커 헤더·출력 토큰을 추가·변경·삭제할 때 통지**하도록 한다.
2026-09-16 에 발효됐다.

v1.18.0(09-20 11:19)은 `HANDOFF_*` 값 10개와 마커 헤더 2종을 추가하면서 **통지하지 않았다.**
깨진 것은 없었다 — 전부 추가였고 소비자는 그대로 돌았다. 문제는 다른 데 있다.

**사람이 재대조할 때까지 아무도 몰랐다.** 계약이 막으려던 것이 정확히 그 간격이고, 계약을
맺는 것만으로는 그 간격이 닫히지 않는다는 것이 실측됐다. 기억해야 하는 절차는 또 빠진다.

### 판정

```
통과      변화 없음 — 대조한 종수를 함께 출력한다
중단 1    통지 필요 — NOTIFIED=1 로 통지를 마쳤다고 선언하면 지나간다
중단 2    대조 불가 — 직전 태그 없음 · ref 를 못 읽음 · 추출이 0종
```

**2 를 0 으로 뭉개지 않는다.** `NOTIFIED=1` 은 통지 필요만 통과시키고 **대조 불가는
통과시키지 않는다** — 통지했다는 선언은 대조했다는 뜻이 아니다.

`NOTIFY_GATE=off` 우회는 "변화 없음" 이 아니라 **"미확인"** 이라고 말한다. 이 구분이
v1.14.2(merge-main 조회 실패) · v1.14.0(app-ads 광고 ID) · v1.19.0(AAB 서명)과 같은 규약이다.

`--publish-only` 는 새 내용이 없어 건너뛰지만, **건너뛴 사실을 출력한다.**

### 이모지 선두 헤더만 고른다

한글도 `§` 도 비ASCII 다. "비ASCII 선두" 로 잡으면 절 제목이 전부 섞인다.

```
이모지 선두만    38종   ← 실제 마커 헤더
비ASCII 선두    379종  ← 한글 절 제목이 섞임
```

## 게이트가 손으로 쓴 통지의 누락을 잡았다

게이트를 만든 직후 `v1.17.0 → v1.18.0` 으로 돌려 봤다. 토큰 10개 외에 **마커 헤더 2종**이
더 있었다.

```
+ ## 🍎 iOS 출시 결과 — <slug>
+ ## 🤖 Android 출시 결과 — <slug>
```

같은 날 사람이 손으로 쓴 통지(ai-chat 이슈 #30)에는 **토큰만 적혀 있었다.** 게이트를 만든
직접적인 이유가 게이트를 만든 당일에 다시 확인된 셈이다. 누락분은 별도로 정정했다.

## 한계

게이트는 **추가·변경·삭제를 탐지할 뿐 통지를 대신하지 않는다.** `NOTIFIED=1` 은 사람의 선언이고
게이트는 그 선언의 진위를 확인하지 않는다. 확인하려면 ai-chat 에 이슈가 실제로 열렸는지를
릴리스 시점에 조회해야 하는데, 릴리스가 네트워크·자격증명에 의존하게 된다. 지금은 하지 않는다.

`E2E_RESULT` 의 허용값과 `HANDOFF_*` 만 본다. **계약 4항의 "그 밖의 기계 판독 토큰" 은
패턴에 없다** — 새 부류가 생기면 `_REL_TOKEN_PAT` 에 추가해야 하고, 그것을 잊으면 이 게이트도
같은 방식으로 조용해진다.
