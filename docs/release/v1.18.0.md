## 설계의 핵심 — 불가역 단계를 격리한다

되돌릴 수 있는 단계를 먼저 끝내고, 불가역 단계는 **사람 확인을 받고** 실행한다.

```
iOS   --dry-run        자격증명·접근·사전 점검만   되돌릴 수 있음
      --archive-only   빌드까지                    되돌릴 수 있음
      --export-only    ipa 로컬 내보내기까지       되돌릴 수 있음
      (없음)           **업로드**                  되돌릴 수 없음
      --submit         **심사 제출**               되돌릴 수 없음

And   --dry-run        편집 세션을 열었다 버림     되돌릴 수 있음
      (트랙 지정)      **edits.commit()**          되돌릴 수 없음
```

**심사 제출을 `--submit` 으로 분리했다.** 기본값은 업로드까지다 — 제출은 되돌릴 수 없고
반려되면 사람이 대응해야 한다.

Android 는 AAB 업로드가 편집 세션 안이라 **세션을 버리면 되돌릴 수 있다.** `commit` 이 경계다.

### 앱 레코드 생성은 스킬이 하지 않는다

자동화는 가능하지만 **이름·기본 언어·번들 ID 가 한 번 정해지면 바꾸기 어렵다.**
`HANDOFF_REQUIRED=app_record` 를 남기고 멈춘다.

**판정 실패 시 신규로 가정하지 않는다.** 신규 경로가 레코드를 만들기 때문이다.
조회가 실패하면 중단한다.

## 각 스킬의 위험 지점

### iOS — 스크린샷 슬롯은 계정마다 다르다

brick-breaker 계정은 6.5"(1284×2778)와 13"(2064×2752)를 받고 6.9"(1320×2868)는 받지 않았다.
**하드코딩하면 계정이 바뀔 때 깨진다.** ASC API 로 조회하고 필요한 해상도만 찍는다.

6.5" 는 **iPhone 14 Plus 시뮬레이터**로 찍는다 — 최신 기기 목록에 그 해상도가 없다.

스크린샷 전에 **광고 초기화를 기다린다.** 실행 직후 캡처하면 배너가 빠진 화면이 찍힌다.

### Android — 업로드 키 분실은 복구 불가

절대 원칙 첫 줄에 뒀다. **잘못된 키로 서명해 올리면 기존 등록의 서명과 달라지고 사후에 고칠 수
없는데, 업로드가 거부될 때까지 드러나지 않는다.**

1·2순위에 값이 둘 다 있고 지문이 다르면 `HANDOFF_DECISION=keystore_conflict` 로 중단한다(v1.17.0).

서비스 계정 JSON 은 **base64 가 아니라 원문 텍스트**다. 스크립트가 reveal 응답의 `.value` 를
한 번 더 `json.loads` 하므로, KMS 가 객체로 파싱하거나 `private_key` 의 `\n` 을 정규화하면 깨진다.

## 사전 점검 — 출시 도중이 아니라 시작 전에 드러나야 한다

brick-breaker 실측(2026-09-19)에서 막힌 것들을 표로 넣었다. **개인정보처리방침 URL 이 404 면
반려된다** — app-portal 배포가 스토어 등록보다 먼저다.

`HANDOFF_REQUIRED` 와 `HANDOFF_DECISION` 을 항목별로 지정했다. 전화번호 국가 코드는 사람 영역이
아니라 **입력 검증**이고, 스크린샷 슬롯도 **스킬이 처리한다**.

## 연령 3축 — 각 스킬이 둘씩 다룬다

| 축 | App Store | Play |
|---|---|---|
| 콘텐츠 등급 | `4+` · `9+` · `12+` · `17+` | IARC |
| 대상 연령층 | **대응물 없음** | 5세 미만 · 6-8 · 9-12 · 13-15 · 16-17 · 18+ |
| 아동 대상 태그 | `/aiops:app-ads` | `/aiops:app-ads` |

**App Store 콘텐츠 등급은 개인화 광고와 무관하다.** Kids Category 선택과 ATT 가 가른다.
등급이 `4+` 라는 이유로 개인화를 끄지 않는다.

**Play 에 14+ 버킷이 없다.** 한국 개인정보보호법의 14세 기준과 어긋나는 회색지대다.

값은 프로젝트 설정으로 받는다. **두 스킬 모두 법률 자문을 하지 않는다.**

## KMS 가 막히면 브라우저로 확인한다

`not_found` 는 미등록인지 권한 없음인지 구별하지 못한다. 그러면 **사람에게 무엇을 시켜야 할지도
모른다** — 계정을 만들라는 것과 키를 등록하라는 것은 다르다.

Chrome 브라우저 도구로 계정·키 존재를 확인하고 결과를 `HANDOFF_VERIFY` 에 담는다.
읽기 전용이며 로그인하지 않는다. 확인하지 못했으면 그 사실을 남긴다 —
**확인하지 않은 것을 확인된 것처럼 적지 않는다.**

## API 호출 3등급

| 등급 | 예 | 정책 |
|---|---|---|
| 1 조회 | 앱 존재 · 현재 버전 · 스크린샷 슬롯 | 자유 |
| 2 멱등 갱신 | 메타데이터 · 스크린샷 · 릴리즈 노트 · AAB 업로드 | 자유 |
| 3 **불가역** | 앱 레코드 생성 · 심사 제출 · `commit` | **사람 확인 필수** |

**3등급 목록이 계약이다.** 새 API 를 쓸 때 어느 등급인지 먼저 판정한다.

## 아직 검증되지 않은 것

**실제 출시는 돌려보지 않았다.** 자격증명이 없고 스토어 제출은 불가역이라 함부로 실행할 수 없다.

첫 검증은 **zen-koi** 가 맡는다(설계 §8 3단계) — 어느 스토어에도 올라가지 않은 유일한 앱이다.
Play 서비스 계정이 KMS 에 등록되고 `verify_access` 가 androidpublisher API 를 실제로 호출하는
시점이 **HANDOFF 계약의 첫 실사용 사례**가 된다.

스킬 3종(`app-pages`·`app-ads`·`app-icon`)과 마찬가지로 이 둘도 **절차를 규정하는 산문**이라
앵커 블록 같은 실행 테스트가 없다. 첫 실사용에서 드러나는 것이 있을 수 있다.
