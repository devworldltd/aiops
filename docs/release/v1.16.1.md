## #29 — 조직 단위 자격증명을 못 찾았다 (가장 심각)

`store_common.py` 의 2단 조회가 **1·2순위 모두 `service` 를 앱 슬러그로 고정**했다.

```python
i.get("service") == slug      # 두 순위 모두
```

조직 공용 자격증명(`appstore_api_key`·`play_service_account`)은 범위 밖이라 `not_found` 가 나고,
**값이 등록돼 있는데 HANDOFF 로 "KMS 에 등록하라" 며 이미 한 일을 하라고 안내한다.**

> 이 세션에서 우리가 사람으로서 저지른 구별 실패(KMS 0건을 부재로 단정)를 **코드가 그대로
> 재현하는** 형태였다.

### 항목이 범위를 선언한다

| 항목 | scope | 이유 |
|---|---|---|
| `ANDROID_KEYSTORE_*` 3종 | `app` | 앱마다 값이 다르다 |
| `APPSTORE_API_KEY_JSON` · `PLAY_SERVICE_ACCOUNT_JSON` | `org` | 조직 공용. 앱마다 같다 |

```
app  1순위 <접두사><종류>@<슬러그>   2순위 <종류>@<슬러그>
org  1순위 <종류>@<조직>             2순위 <접두사><종류>@<슬러그>
```

`org` 의 2순위가 **이관 전 상태**다 — `PONG_APPSTORE_API_KEY_JSON@pong` 이 정확히 그것이고,
`legacy` 표시가 없으면 **이관이 영원히 끝나지 않는다.**

모르는 항목은 `app` 으로 본다. 조직 공용으로 잘못 넓히는 것보다 안전하다.

**`service` 를 아예 빼지 않는다.** 빼면 다른 앱의 동명 시크릿이 섞여 `ambiguous` 가 난다.
scope 에 따라 **고정 대상만** 바뀐다.

### HANDOFF_VERIFY 에 조회 범위를 남긴다

```
HANDOFF_VERIFY=kms:not_found (APPSTORE_API_KEY_JSON@devworld · PONG_APPSTORE_API_KEY_JSON@pong)
```

"못 찾았다" 를 받은 사람이 **범위 밖인지 진짜 없는지 스스로 판단**할 수 있어야 한다.

## #27 — 웹 신호 탐색이 루트에만 한정

- **배포 매니페스트를 깊이 3까지** 찾는다. 모노레포는 `apps/*/` 아래에 있다.
  §15 가 모바일을 깊이 3·6 으로 보는 것과 균형을 맞췄다
- **Java · Kotlin 웹 프레임워크 추가** — `spring-boot`·`ktor`·`micronaut`·`quarkus`·`javalin`.
  Gradle·Maven 을 웹 신호에서 뺐으므로(v1.15.1) 그 전에는 Java 웹을 잡을 방법이 없었다

**빌드 파일의 존재가 아니라 내용을 본다.** Android 도 Gradle 을 쓰므로 존재만으로는 여전히
웹이 아니다 — 테스트 `W1` 이 이 회귀를 막는다.

> 제보된 devworld-blog 반례 **자체는 성립하지 않았다.** 프레임워크 의존성은 이미 깊이 3까지
> 보고 있어 `hono` 가 잡혔고, 같은 구조의 모노레포 6개 전부 `web=true` 였다.
> 다만 제기된 격차 둘은 실재해 고쳤다.

## #28 — 판정 근거가 기록되지 않았다

v1.15.1 이 `signal` 을 **출력**했지만 기록하지 않았다. 세션이 끝나면 근거가 사라지고, 나중에
`agent_hints.platform` 만 보면 신호 판정인지 폴백인지 알 수 없다.

`§16-1` `setup:platform-signal-write` 신설.

```jsonc
{ "platform": "web", "platform_signal": "apps/blog/wrangler.jsonc" }
{ "platform": "web", "platform_signal": "none (fallback)" }
```

`platform_signal` 이 `none (fallback)` 이면 **감지가 아무것도 찾지 못한 상태**다. 이 config 를
읽는 쪽(`/aiops:mobileflow` 라우팅, `dev-mobile-*` 분기)은 값을 신뢰하기 전에 이 필드를 본다.

§19 보존 목록에 추가해 재실행 시 감지 실패가 기존 근거를 덮지 않게 했다.

**실행 순서 제약**: §19 가 `.agent_hints` 를 통째로 덮어쓰므로 그 뒤에 와야 한다(§20 과 같다).

## 확인해 주셔야 할 것

**`service=devworld`·`pong` 은 우리 토큰으로 보이지 않아 실측하지 못했다.** scope 동작은 zen-koi 가
확인해야 한다.

캐시 갱신이 필요하다 — `claude plugin marketplace update aiops` → `claude plugin update aiops` →
세션 재시작. 소스만 갱신하면 반영되지 않는다.
