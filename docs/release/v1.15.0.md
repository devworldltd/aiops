## ⚠️ 계약 #1 통지 — `aiops-codex` 대상

**이 릴리스는 마커 계약에 토큰을 추가한다.** 계약 #1(마커·출력 계약 변경 시 aiops-codex 통지)에
따라 릴리스와 동시에 통지한다.

| 구분 | 토큰 | 비고 |
|---|---|---|
| 추가 | `HANDOFF_REQUIRED=<항목코드>` | 순수 사람 영역 |
| 추가 | `HANDOFF_DECISION=<항목코드>` | 결정 대기 — 스킬이 선택지 제시 의무 |
| 추가 | `HANDOFF_ACCESS=<접근권한>` | 필요한 접근 권한 |
| 추가 | `HANDOFF_VERIFY=<확인코드>` | 완료 확인 방법 |
| 추가 | `HANDOFF_CLEARED=<항목코드>` | 해소 |
| 추가 | `## ⏸️ 사람 확인 대기` | 헤더 |
| 추가 | `## ✅ 사람 확인 완료` | 헤더 |

**변경·삭제 없음.** 기존 토큰(`E2E_RESULT`·`PROD_RESULT`·`E2E_ENV_ERROR`)과 마커 헤더는 그대로다.

**추가는 안전하다** — 기존 게이트가 새 토큰을 grep 하지 않으므로 소비자가 전사하지 않아도 깨지지 않는다.

## 무엇을 위한 계약인가

**완료 표시만 되고 실제로는 안 된 상태가 가장 위험하다.** 이 실패 모드는 런타임과 무관하다.

산문으로만 "여기서 멈추고 사람에게 넘긴다" 고 적으면 **멈췄는지 아닌지 아무도 판정할 수 없다.**
후속 단계가 앞 단계의 중단을 모르고 진행하는 것을 막으려면 기계가 읽을 수 있어야 한다.

## 설계 결정 셋

### REQUIRED 와 DECISION 을 나눈다

둘을 한 토큰으로 두면 **스킬의 의무가 사라진다** — "사람이 알아서 하세요" 로 끝내도 규약 위반이
아니게 되기 때문이다.

| | `HANDOFF_REQUIRED` | `HANDOFF_DECISION` |
|---|---|---|
| 스킬이 할 수 있는 것 | 없음 | **선택지를 계산해 제시해야 한다** |
| 재개 확인 | 사람 보고에 의존 | **기계적으로 확인 가능** |

게이트 차단 효과는 같다. 다른 것은 토큰에 붙는 의무다.

### 역할이 아니라 접근 권한으로 정의한다

`account_owner`·`admob_console_admin` 같은 역할명으로는 받는 사람이 무엇을 해야 하는지 모른다.
소규모 조직에서는 그것들이 실질적으로 같은 사람이다.

```
appstore_account · play_console · admob_console · mailbox:<주소> · kms
```

한 사람이 여러 권한을 겸해도 메시지가 정확하다.

### 확인은 산출물에서 한다, 보고에서 하지 않는다

```
릴리스 → 소스 레포 갱신 → 플러그인 캐시 갱신 → 세션 재시작 → 실제 사용
```

2026-09-20 실측: 소비자가 두 번째 단계까지 하고 그것을 "갱신했다" 로 알고 있었다. 플러그인이
`directory` 소스라 캐시가 설치 시점에 복사되고 소스 변경이 자동 반영되지 않았다. 세션은 계속
옛 버전을 로드했다.

**"했다고 함" 과 "된 것이 반영됨" 은 다르다.** 확인은 소스가 아니라 실제 로드되는 산출물에서 한다.

## 게이트 규약 4종

1. **해소 댓글은 REQUIRED·DECISION 토큰을 인용하지 않는다** — 인용하면 grep 이 그 문장에 걸려
   영구 차단된다. forge 에 댓글 삭제가 없어 되돌릴 수 없다(`/aiops:merge-main` #49 와 같은 함정)
2. **개수로 판정한다** — `count(REQUIRED|DECISION) > count(CLEARED)` 이면 차단
3. **조회 실패는 통과가 아니다** — v1.14.2 와 같은 원칙
4. **확인은 산출물에서 한다**

## 충돌 검토를 테스트로 강제했다

`HANDOFF_` 접두사는 기존 판정 토큰과 양방향으로 부분 문자열 관계가 없다. v1.11.0 의
`PASS_DRY_RUN` 사례는 재발하지 않는다.

**이 검토를 문서에만 적으면 다음 토큰을 추가할 때 잊는다** — `PASS_DRY_RUN` 이 그렇게 생겼다.
`aiops/tests/handoff-marker-contract.test.sh` 16건이 토큰 간·기존 토큰과의 부분 문자열 관계,
헤더 이모지 충돌, 규약 4종 존재를 검사한다.

`REQUIRED`/`DECISION` 분리 근거가 문서에 남아 있는지도 검사한다 — 나중에 "합치자" 는 제안이
다시 나왔을 때 근거가 사라지지 않게 하려는 것이다.

### 변이 테스트에서 테스트 자신의 결함이 나왔다

`HANDOFF_E2E_RESULT=PASS` 를 넣어도 통과했다. 추출 정규식 `HANDOFF_[A-Z]+` 가 이름을
`HANDOFF_E` 로 잘라(`2` 가 `[A-Z]` 밖) 충돌 검사가 헛돌고 있었다. 숫자를 포함하도록 고치고
기존 토큰을 이름·전체 두 수준으로 비교하게 했다.

**이번 시리즈에서 세 번째로 나온 같은 종류다** — 검사하는 척하는 검사.
