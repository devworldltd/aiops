## 키스토어 생성·보관 절차 (§3-1)

v1.18.0 의 `android-release` 는 키스토어가 **이미 있다고 전제**했다. 없을 때 무엇을 하는지가
없었다 — "분실하면 복구 불가" 한 줄만 있고 생성 절차도, 보관 방식도, 보관이 제대로 됐는지
확인하는 방법도 없었다. zen-koi 가 이 부분을 사용자와 정하겠다고 한 상태였다.

### "복구 불가" 는 조건부다

기존 절대 원칙 1은 뭉뚱그려 단정했는데, 실제로는 세 갈래다.

| 키 | 누가 보관 | 분실 시 |
|---|---|---|
| 앱 서명 키 | Play App Signing 가입 시 Google | 개발자가 잃을 수 없다 |
| 업로드 키 | 개발자 | Play Console 에서 재설정 요청 가능 |
| 앱 서명 키 (Play App Signing 미가입 레거시) | 개발자 | 복구 불가 |

2021년 8월 이후 신규 앱은 AAB 필수이며 Play App Signing 에 자동 가입된다. 따라서 새로 만드는
앱의 업로드 키는 **재설정이 가능하다.**

**다만 이 표를 근거로 방심하지 않는다.** 재설정에는 절차·대기·승인이 붙고 그동안 업데이트가
막힌다. 정책도 바뀐다. 레거시 앱이라면 마지막 행이 그대로 적용되며 그때는 진짜로 끝이다.

### 절차

```
생성    keytool -genkeypair  PKCS12 / RSA 2048 / validity 10000, 비밀번호는 난수
보관    KMS 3종 동시 등록 (_BASE64 · _PASSWORD · _KEY_ALIAS), scope=app
검증    KMS 에서 복원해 지문 왕복 비교 — 같아야 서명한다
정리    원본 shred -u, .gitignore 에 *.jks · *.keystore
```

**세 개가 한 벌이다.** 하나라도 빠지면 서명할 수 없고, 그 사실은 빌드가 아니라 **업로드에서**
드러난다.

## 문서에 적은 명령이 틀렸고, 돌려봐서 잡았다

처음 적은 왕복 검증 명령은 `grep 'SHA-256:'` 이었다. 한국어 로케일 keytool 은 `SHA256:` 으로
출력한다 — **아무것도 잡지 못했다.** 그리고 그 상태에서 `[ "$F1" = "$F2" ]` 가 빈 문자열끼리
비교해 **통과로 판정됐다.**

```bash
# 레이블을 잡지 말고 32바이트 16진 패턴을 잡는다 (SHA-1 은 20바이트라 걸리지 않는다)
keytool -list -v -keystore "$1" -storepass "$2" 2>/dev/null \
  | grep -oE '[0-9A-F]{2}(:[0-9A-F]{2}){31}' | head -1
```

빈 지문도 실패로 떨어뜨리도록 했다. 이 레포가 #119 이후 반복해 걸러온 **"검사 못 함 ≠ 통과"**
가, 하필 그것을 설명하는 문서의 예제 명령에서 났다.
