## ⚠️ 먼저 — 모바일 감지 버그를 고쳤다 (기존 사용자 영향)

**`/aiops:setup` §15 가 `android/` 래퍼를 쓰는 레포를 통째로 놓치고 있었다.**

```
find . -maxdepth 4 -name "AndroidManifest.xml"     ← v1.13.2 까지
./android/app/src/main/AndroidManifest.xml         ← 실제 위치, 깊이 5
```

깊이 4로는 잡히지 않아 `ANDROID_DETECTED=false` 가 되고, `platform` 이 `mobile` 로 판정되지 않는다.
그러면 `agent_hints.mobile` 이 기록되지 않아 **`/aiops:mobileflow` 진입 라우팅과 `dev-mobile-*`
분기가 동작하지 않는다.** 빌드가 깨지는 게 아니라 모바일 경로 자체가 없는 것처럼 보이는 종류의 실패다.

`android/`·`ios/` 래퍼 디렉터리를 두는 레포가 모두 해당된다. 단일 모듈 레포(`app/src/main/…` 이 루트
바로 아래, 깊이 4)는 영향이 없어 지금까지 드러나지 않았다.

**조치**: `maxdepth 6` + `build/` prune. 회귀 테스트 T11·T13 을 두었다.

**기존 사용자가 할 일**: 모바일 레포에서 `/aiops:setup` 을 다시 실행한다. `.claude/config.json` 의
`agent_hints.mobile` 이 기록되면 된다. 자가 확인:

```bash
cd <레포> && find . -maxdepth 4 -name AndroidManifest.xml -print -quit
```

아무것도 안 나오는데 앱에 매니페스트가 있으면 이 건에 해당했던 레포다.

## 새 기능 1 — `/aiops:setup` §20 모바일 앱 역량 감지

대상 레포가 **실제로 무엇을 하는지**를 읽어 `agent_hints.mobile.capabilities` 에 기록한다.

| 항목 | 읽는 곳 | 공통 토큰 |
|---|---|---|
| 권한 | AndroidManifest `uses-permission` · Info.plist `NS*UsageDescription` | `camera`·`microphone`·`location`·`photo_library`·`contacts`·`notifications`·`bluetooth`·`tracking`·`internet` |
| SDK | Gradle · SPM · Pod · npm · pub 의존성 | `admob`·`ump`·`firebase_analytics`·`crashlytics`·`google_signin`·`iap`·`sentry` |
| 지원 언어 | Android `res/values-*` · iOS `*.xcstrings` · `*.lproj` | BCP-47 (`ko`·`zh-Hans`·`zh-Hant` …) |

설계 원칙 셋이 중요하다.

- **선언된 것만 적는다.** 매니페스트·plist·의존성에 없는 것을 추론하지 않는다.
- **기본 언어는 추론하지 않는다.** Android `res/values/` 는 한정자가 없어 어느 언어인지 기계적으로
  알 수 없다. iOS `sourceLanguage` 가 있으면 쓰고, 없으면 `languages_base_unknown: true` 로 남겨
  사람이 확인하게 한다. 짐작해서 채우면 문서에 없는 언어 칸이 생긴다.
- **감지 0건도 기록한다.** `sources` 에 읽은 파일을 남겨 "미감지" 와 "선언 없음" 을 구별한다.

`tracking` 을 한 토큰으로 수렴시킨 것이 실질이다. Android 는 `AD_ID`·`ACCESS_ADSERVICES_*`, iOS 는
ATT 키로 **서로 다른 자리에** 선언되어 한쪽만 보면 놓친다.

### 실행 순서 제약

§19 가 `.agent_hints` 를 통째로 덮어쓰므로 **capabilities 기입은 반드시 그 뒤에 온다.**

```
§15 모바일 감지 → §16 platform → §13·§19 agent_hints → §20 감지 → §20 기입 → §14 확인 UI
```

## 새 기능 2 — 앱 문서·광고·아이콘 스킬 3종

| 스킬 | 하는 일 |
|---|---|
| `/aiops:app-pages` | app-portal 입력 JSON 생성 (`content/<slug>/*.json` + `apps.json` 항목). **페이지 HTML 을 쓰지 않는다** — 생성기가 만든다. 손으로 쓰는 것은 `support/index.html` 과 `_headers` 한 줄뿐 |
| `/aiops:app-ads` | AdMob 배너·전면 + UMP 동의. 테스트 ID 게이트 강제, 실기동 실패 3건 사전 차단 |
| `/aiops:app-icon` | 외부 에셋 없이 코드로 아이콘 생성. Android 적응형(+`monochrome`) · iOS 1024 PNG |

셋 다 입력은 §20 감지 계층이다. **감지되지 않은 것을 쓰지 않는다** — 법적 문서에 없는 권한이
섞여 들어가는 것을 막는 것이 이 연결의 목적이다.

`/aiops:app-pages` 와 `/aiops:app-ads` 는 **배포·콘솔 조작을 하지 않는다.** `wrangler deploy`,
AdMob 콘솔 설정, 스토어 제출은 사람이 한다. 안내만 한다.

## 그 밖

- `dev-mobile-{android,ios,rn,flutter}` 에 `capabilities` 읽기 경로 추가. 기존
  `agent_hints` → `profile.yaml` 우선순위를 그대로 따른다
- §19 보존 목록에 `agent_hints.mobile.capabilities` 추가 — 재실행 시 감지 실패가 기존 값을
  빈 목록으로 덮지 않는다

## 역호환

깨지는 변경 없음.

| 상황 | 동작 |
|---|---|
| `capabilities` 없는 기존 config | 빈 목록 취급 |
| `mobile` 키 없는 웹 전용 config | `mobile` 키를 만들지 않는다 |
| `platform=web`·`cli` | §20 기입 생략 |
| jq 부재 · config 부재 · 깨진 JSON | 원본 바이트 불변 + 경고 |

## 검증

- 신규 테스트 48건(감지 20 + 언어 8 + 배선 20) → **전체 484건 통과**, 기존 436건 회귀 없음
- 실제 레포 종단 실행(zen-koi): `permissions=[internet, tracking]` · `sdks=[admob, ump]` ·
  `languages=[de, en, es, fr, ja, ko, zh-Hans]` — 실제 선언과 일치
- app-portal 실물 대조로 `platforms` 스키마와 번역 관례를 확인해 스킬 기술을 정정

## 알려진 한계

- 신규 스킬 3종은 절차를 규정하는 산문이라 앵커 블록 같은 실행 테스트가 없다. 첫 실사용에서
  드러나는 것이 있을 수 있다
