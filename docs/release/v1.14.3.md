**플러그인 배포물(`aiops/`)은 바뀌지 않았다.** `tools/` 는 이 레포의 릴리스 도구이며 소비자에게
배포되지 않는다. 이 버전은 **이력을 남기기 위한 것**이고, v1.14.2 를 쓰는 소비자가 갱신해야 할
이유는 없다.

## 무엇을 고쳤나 — 하지 않은 일을 했다고 보고했다

`--publish-only` 는 사내 태그를 만들지도 `latest` 를 옮기지도 않는다. 그런데 완료 메시지가
`if/else` 바깥에 있어 두 모드 모두에서 출력됐다.

```
── --publish-only: 사내 태그 생성 건너뜀 (v1.14.1 이미 존재) ──
✓ v1.14.1 생성 · latest → 0c6d61a 이동 완료.     ← 하지 않았다
```

**바로 앞 줄에서 "건너뜀" 이라고 해 놓고 다음 줄에서 "생성 완료" 를 말한다.**

v1.14.1 공개본 게시를 재시도할 때 실제로 이 출력이 나왔다. 사내 태그가 이미 있는 상태였으므로
실질적 피해는 없었지만, **출력만 보면 태그를 새로 만든 것으로 읽힌다.**

## 조치

- 완료 메시지를 **각 분기 안으로** 옮긴다
- publish 모드는 실제 한 일만 말한다 — `ℹ️ 사내 태그·latest 는 건드리지 않았습니다 — 공개본만 게시합니다`
- 앵커 블록(`release:tag-or-skip`)으로 만들어 테스트가 코드를 직접 실행

## 검증

- `aiops/tests/release-tag-or-skip.test.sh` 10건 신규 → **전체 521건 통과**
- `git` 스텁으로 태그·push 호출을 기록해 모드별로 검사한다

이 버그는 **"동작은 맞는데 보고가 틀린"** 종류라 두 축을 나눠 확인한다.

| 검사 | 무엇을 |
|---|---|
| `R2` | publish 모드가 실제로 아무것도 만들지 않음 — 호출 기록으로 확인 |
| `R3` | 그 사실을 정직하게 보고함 — 출력으로 확인 |

**변이 테스트**: 메시지를 분기 밖으로 되돌리면 2건이 실패한다.

## 이 결함이 놓인 자리

`tools/release.sh` 는 2026-09-16 사고(공개본 push 가 403 으로 실패했는데 "게시 완료" 를 출력)
이후 push 실패 확인을 넣었고, 그 경위가 스크립트 주석에 남아 있다. **같은 부류를 하나 더
남겨두고 있었다** — 실패가 아니라 "하지 않은 일" 쪽이었다.

v1.14.1 · v1.14.2 · v1.14.3 은 모두 같은 축의 결함이다.

| 버전 | 무엇이 어긋났나 |
|---|---|
| v1.14.1 | 검사 못 함 ≠ 위반 없음 (`app-ads` 게이트) |
| v1.14.2 | 검사 못 함 ≠ 마커 없음 (`merge-main` 조회) |
| v1.14.3 | 한 일 ≠ 보고한 일 (`release.sh` 출력) |

셋 다 **실패가 조용한** 쪽이다.
