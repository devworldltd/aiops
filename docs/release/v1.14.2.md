## ⚠️ 릴리스 경로의 게이트가 조용히 열려 있었다

**`/aiops:merge-main` 이 이슈 댓글 조회 실패를 "마커 없음" 과 같게 취급했다.**

```bash
ISSUE_COMMENTS=$(bash ".../forge.sh" issue-comments "$RECENT_ISSUE" 2>/dev/null)
```

종료 코드를 버리고 stderr 를 삼킨다. 다음 상황에서 출력이 빈다.

- forge(Gitea/GitHub) 장애 또는 네트워크 단절
- `REVIEWER_TOKEN` 등 토큰 만료
- 사내 forge 앞단의 Cloudflare Access 토큰 만료

이때 결과는 **"이슈 #N 댓글 0건"** 이다. 실제로 댓글이 없는 것과 구별되지 않는다.

`e2e_required_for_merge_main` 은 **기본값이 `false`(완화 모드)** 다. 완화 모드에서는 마커가 없어도
진행하므로, 조회 실패 시 차단 마커도 PASS 마커도 없는 상태가 되어 **E2E 검증 없이
dev → main 머지가 진행된다.**

**실패처럼 보이지 않는다.** 로그에는 "댓글 0건 — e2e_required_for_merge_main=false 로 진행" 이
찍히고, 머지는 성공한다.

## 조치

```
rc ≠ 0  → comments_fetch_failed 로 차단
rc = 0  → 종전대로 (댓글 0건이면 완화 모드에서 진행)
```

**`e2e_required_for_merge_main` 값과 무관하게 차단한다.** 완화 모드의 뜻은
"마커가 없어도 진행" 이지 **"검사를 못 해도 진행" 이 아니다.** 둘을 같게 두면 장애가 났을 때
가장 위험한 쪽으로 열린다.

stderr 를 버리지 않고 앞 3줄을 보여 원인(토큰 만료인지 네트워크인지)을 바로 알 수 있게 했다.

게이트를 앵커 블록(`merge-main:comments-fetch`)으로 만들어 테스트가 문서의 코드를 직접 실행한다.

### 사유 코드 추가 (11종 → 12종)

| 사유 코드 | 발생 조건 |
|---|---|
| `comments_fetch_failed` | §4.1 조회가 `rc≠0` 으로 실패 — **검사를 수행하지 못함.** 완화 모드에서도 차단 |

## 이 결함을 어떻게 찾았나

v1.14.1 에서 고친 `app-ads` §6-1 과 **같은 결함 계열**을 기존 게이트에서 점검하다 나왔다.
"검사 못 함" 과 "검사했더니 없음" 을 한 결과로 뭉개는 패턴이다.

앵커 14종을 전수로 보았다.

| 대상 | 판정 |
|---|---|
| healthcheck 게이트 3종 (`merge-pr`·`deploy-prod`·`verify-deploy`) | **안전** — 스킵하려면 `platform=cli` 가 명시적으로 있어야 하고, 설정 읽기가 실패하면 검사 쪽으로 떨어진다 |
| `merge-main` 마커 판정 | **안전** — 허용 조건이 AND 화이트리스트라 조회가 비어도 통과하지 못한다 |
| `merge-main` §4.1 조회 | **결함** — 이번 수정 대상 |
| `merge-pr` §14.4 의 같은 패턴 | 문서 예시이며 실행 경로가 아니다 |
| `setup:*` 앵커 | 게이트가 아니라 감지 로직 |

깨진 곳은 마커 판정이 아니라 **그 앞의 조회 단계**였다. 판정 로직만 보면 안전해 보이는 종류다.

## 검증

- `aiops/tests/merge-main-fetch-failure.test.sh` 12건 신규 → **전체 511건 통과**
- `forge.sh` 스텁으로 세 경우를 만든다: `rc≠0` / `rc=0`+빈 출력 / `rc=0`+내용
- `M4` 는 조회 실패와 댓글 0건의 결과가 **서로 다름을 직접 검사**한다
- **변이 테스트**: 예전 동작(`2>/dev/null`·rc 버림)으로 되돌리면 12건 중 7건이 실패한다

## 역호환

깨지는 변경 없음. 정상 동작(조회 성공)에서는 종전과 같다. 달라지는 것은 **조회가 실패하던 경우**이며,
이는 이전에 "댓글 0건" 으로 잘못 보고되던 상황이다.

`comments_fetch_failed` 사유 코드가 새로 나올 수 있다. 이 문자열을 grep 하는 소비자는 없었으므로
마커 계약(#119)에는 영향이 없다.

## 점검의 한계

**이 결함 계열만 겨냥했다.** 앵커 밖 산문에 적힌 명령과 에이전트 정의(`agents/*.md`) 안의 판정
로직은 보지 않았다. 게이트 성격의 grep 이 13개 스킬 파일에 흩어져 있고 그중 실행 경로인 것만 추렸다.
