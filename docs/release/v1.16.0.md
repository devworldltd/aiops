## 조용히 틀릴 수 있는 지점 셋

### 1. 버전 정본이 `pbxproj` 가 아니다

XcodeGen 레포의 정본은 `project.yml` 이다. `pbxproj` 는 생성물이라 `generate` 를 안 했으면
옛 값이 나온다.

**빌드는 성공하고 스토어에 잘못된 버전이 올라간다.** 실패처럼 보이지 않는다.

`pbxproj` 가 `project.yml` 보다 오래되면 **중단**하고 `xcodegen generate` 를 안내한다.
`project.yml` 이 없는 레포는 종전대로 `pbxproj` 를 읽는다.

### 2. KMS 조회 0건은 "미등록" 이 아니다

권한 없는 토큰도 HTTP 200 에 빈 items 로 온다. **구별할 방법이 없다.**

이번 시리즈에서 실제로 겪었다 — 조회가 0건이라 "자격증명이 없다" 고 보고했는데, 다른 토큰으로는
보였다. 가시성 한계였다.

`KmsResult` 가 여섯 상태를 구별하고 **`ok` 만 통과**시킨다.

```
ok · token_missing · not_found · fetch_failed · ambiguous · no_value
```

`not_found` 의 `detail` 에 "0건은 미등록과 권한 없음을 구별하지 못합니다 — 토큰 스코프도 함께
확인하세요" 를 적는다. `KmsResult.handoff()` 가 계약(v1.15.0) 형식의 마커를 만든다.

### 3. `KMS_TOKEN` 이 레포 안에 없다

```
/Users/devworld/src/game/.envrc      ← KMS_TOKEN
/Users/devworld/src/game/zen-koi/    ← 레포. .envrc 없음
```

레포만 보면 못 찾는다. 위로 거슬러 올라가며 찾고, 못 찾으면 `token_missing` 으로 중단한다.

## 시크릿 이름 규칙 (설계 §2-4 확정)

```
service     = zen-koi                          슬러그 그대로
SECRET_NAME = ZEN_KOI_APPSTORE_API_KEY_JSON    하이픈 → 언더스코어, 대문자
```

조회는 **두 번 시도한다.** 새 규칙으로만 찾으면 이미 등록된 무접두사 시크릿
(`ANDROID_KEYSTORE_BASE64` 등)이 깨진다.

```
1순위  ZEN_KOI_ANDROID_KEYSTORE_BASE64  + service=zen-koi
2순위  ANDROID_KEYSTORE_BASE64          + service=zen-koi
```

2순위로 찾으면 `legacy=True` 로 표시해 호출 측이 보고에 남긴다 — 옛 규칙이며 언젠가 옮겨야 한다.
**조용히 넘어가면 혼재가 영구화된다.** 새로 등록하는 것은 1순위 형식만 쓴다.

이것은 **기반**이지 업로드 스크립트가 아니다. 다음이 남아 있다.

- `xcodebuild archive` → `exportArchive` 실행
- `androidpublisher v3 edits` API 호출
- ASC API 접근 확인 (JWT 서명)
- 릴리즈 노트를 `content/` 에서 읽는 경로

그리고 **실제 업로드는 검증되지 않았다.** 자격증명이 없고, 스토어 제출은 불가역이라 함부로 돌릴
수 없다. 첫 검증은 zen-koi 가 맡는다(설계 §8 3단계) — 어느 스토어에도 올라가지 않은 유일한 앱이다.
