`ScanBarcode/scripts/` 의 앱 전용 스크립트를 일반화했다. `--slug` 하나만 주면 나머지를 찾는다.

  version=1.0.0 (project.yml)    package=kr.co.devworld.zenkoi

만드는 **그 파일**이며 정본이 하나로 이어진다.

### 불가역 경계를 단계로 나눴다

```
--dry-run       자격증명·접근만 확인            되돌릴 수 있음
--archive-only  빌드까지만                      되돌릴 수 있음
--export-only   ipa 를 로컬에 내보내기까지만    되돌릴 수 있음
(없음)          **실제로 업로드한다**           되돌릴 수 없음
```

`--export-only` 가 이번에 생겼다. **불가역 동작이 한 단계로 격리되어야 사람 확인을 붙일 자리가
생긴다.**

## ⚠️ 1·2순위가 둘 다 있을 때 조용히 1순위를 쓰고 있었다

v1.16.1 의 2단 조회는 **첫 hit 에서 반환**했다. 둘 다 존재하고 값이 다르면 그 사실이 드러나지
않는다.

**키스토어가 이 흐름에서 조용한 실패 비용이 가장 크다.** 잘못된 키로 서명해 올리면 기존 등록의
서명과 달라지고 **사후에 고칠 수 없는데, 업로드가 거부될 때까지 드러나지 않는다.**

| 상태 | 처리 |
|---|---|
| 지문이 같다 | 1순위 사용 + `duplicate=identical` 로 보고. 정리 대상이지만 진행 가능 |
| 지문이 다르다 | `duplicate_conflict` 로 **중단**. 추측하지 않는다 |

지문은 값의 SHA-256 앞 8자다. **값을 노출하지 않고 같은지만 비교**하므로 보고에 남겨도 안전하다.

충돌은 `HANDOFF_DECISION` 으로 낸다 — 스킬이 **어느 이름에 어떤 지문이 있는지 제시할 수 있으므로**
계약 v1 의 분리 기준상 DECISION 이다. 그 밖의 실패는 `HANDOFF_REQUIRED` 그대로다.

## ⚠️ ExportOptions 의 `destination` 이 `upload` 였다

기존 두 레포(`ScanBarcode`·`pong`)의 실제 파일은 **둘 다 `export`** 다.

`upload` 로 두면 `exportArchive` 가 그 자리에서 App Store Connect 로 올린다. **내보내기와 업로드가
한 명령에 붙어** 불가역 동작을 떼어낼 수 없고, 사람 확인을 붙일 자리가 없어진다.

생성 템플릿을 `export` 로 바꾸고 `signingStyle=automatic` · `stripSwiftSymbols` 를 기존 레포와
맞췄다. 업로드할 때만 **메모리에서** `upload` 로 바꿔 임시 파일로 넘기므로 디스크 파일은 그대로다.

**기존 파일은 덮어쓰지 않는다** — 한 레포에 AppStore·TestFlight 용이 따로 있고 내용이 다르다.

## 버전 staleness 를 mtime 에서 값 비교로 (v1.17.0 포함)

zen-koi 실측에서 **오탐이 났다.** pbxproj 가 project.yml 보다 2분 오래됐지만 버전은 둘 다
`1.0.0` 이었다 — 마지막 수정이 **서명 팀 설정 변경**이었고 버전과 무관했다.

막아야 하는 것은 "generate 를 안 해서 **버전이 갈린** 상태" 뿐이다. 값을 비교하고, 갈렸으면
양쪽 값을 모두 보여준다.

mtime 은 세 경우에서 틀린다 — 클린 클론(pbxproj 부재, 비교할 왼쪽 항이 없음) · `rsync -a`·`tar -p`
(mtime 보존, 내용은 바뀜) · `git checkout`(과잉 판정). 값 비교는 셋 다 맞다.

## 설계 문서 — org legacy 폴백은 이관 유예다

`scope=org` 의 2순위는 `<접두사><종류>@<현재 앱 슬러그>` 이므로 **사본을 가진 앱 하나만** 구제한다.
`pong` 은 잡히지만 `zen-koi` 가 찾는 `ZEN_KOI_APPSTORE_API_KEY_JSON@zen-koi` 는 **영원히 존재하지
않는다.**

이 동작 자체는 맞다 — 한 앱이 다른 앱의 네임스페이스를 뒤지면 권한 경계를 넘는다.
바뀌는 것은 결론이다: **이관은 선택이 아니라 두 번째 앱 출시의 선행 조건이다.**

## 아직 검증되지 않은 것

**실제 업로드는 돌려보지 않았다.** 자격증명이 없고 스토어 제출은 불가역이다. 첫 검증은 zen-koi 가
맡는다(설계 §8 3단계) — 어느 스토어에도 올라가지 않은 유일한 앱이다.

Play 서비스 계정이 KMS 에 등록되면 `verify_access` 로 androidpublisher API 를 실제 호출해 권한까지
확인하는 것이 **HANDOFF 계약의 첫 실사용 사례**가 된다.
