## 1. 불가역 항목이 넷 중 하나가 아니라 다섯 중 둘이었다

zen-koi 가 콘솔 화면에 적힌 문구를 보고 알렸다. 공식 문서로 확인하니 **그쪽 보고보다 강했다.**

> 앱을 무료로 제공한 후에는 유료로 변경할 수 없습니다. 앱을 유료로 변경하려면
> **새 패키지 이름으로 새 앱을 만들고** 가격을 설정해야 합니다.

"게시 후" 가 아니라 **"무료로 제공한 후"** 이고, 복구 경로가 다른 불가역 항목(패키지명)을 다시
요구한다. **두 항목이 사실상 하나로 묶여 있다.** 반대 방향(유료→무료)은 가능하다 — 양방향 불가로
뭉개지 않는다.

## 2. 확정 시점 — 근거 둘이 엇갈린다

```
Play 고객센터   '앱 만들기' 절차에 패키지명 입력 단계가 없다
zen-koi 실측     폼이 패키지명을 직접 입력받고 '사용 가능 여부 확인' 까지 했다
```

**어느 쪽인지 단정하지 않는다.** 고객센터가 UI 변경을 못 따라왔을 수도, 계정·지역·콘솔 버전 차이일
수도 있다. 다만 **보수적인 쪽으로 다룬다** — 이 스킬 안에서 확정된다고 가정한다.

```
여기서 확정 가정 + 실제는 나중   경고를 한 번 더 본 것뿐
나중 가정 + 실제는 여기서 확정   "아직 되돌릴 수 있겠지" 로 지나간다
```

§5 문구를 "지금 이 화면에서 고정됩니다" 로 바꿨다. 경고는 **두 줄에만** 단다 — 전부에 달면 사람이
둘을 구별해 읽지 못한다.

## 3. v1.21.0 이 계약 위반을 내보냈다

```
console ⊂ store_console_session
```

계약 #1 의 "새 값이 기존 값의 부분 문자열이면 안 된다" 위반이다. `HANDOFF_VERIFY=console`(v1.18.0)이
안에 들어 있어, 앵커 없이 `console` 로 grep 하면 둘이 같이 잡힌다.

**v1.21.0 통지(#35)에서 "부분 문자열 포함 없음" 이라고 적었는데 틀렸다.**

```
HANDOFF_REQUIRED=store_console_session   → store_session_missing
```

릴리스된 값의 변경이므로 **파괴적**이고, 계약대로 릴리스 전에 통지했다(#36).

## 4. 왜 v1.21.0 에서 안 잡혔나 — 검사가 HEAD 를 봤다

`release-notify-gate` 의 E6 이 `git grep HEAD` 를 썼다. **커밋 전에 스위트를 돌리면 새 값이 보이지
않는다.** 그래서 "충돌 없음" 이 나왔고 그대로 릴리스됐다.

작업 트리를 보도록 고쳤고, HEAD 와 갈리면 그 사실을 출력한다. 되돌려 확인했다 — 충돌값을 복원하니
즉시 FAIL 로 잡힌다.

**위반이 릴리스된 뒤에야 잡히는 검사는 검사가 아니다.** v1.20.0 통지 게이트를 만들 때 한 말을,
그 게이트에 딸린 검사가 어기고 있었다.
