## /aiops:app-record — 스토어 앱 레코드 생성

zen-koi 요청(#34)이다. `android-release` · `iphone-release` 가 `HANDOFF_REQUIRED=app_record` 로
멈추는 지점을 넘긴다. **계정 발급·키 발급과 달리 신규 앱마다 매번 필요하다.**

### 설계를 바꾼 확인 — 요청자의 전제가 틀렸다

요청서는 "iOS 는 ASC API 로 앱 레코드 생성 가능(`POST /v1/apps`)" 이라고 적었다. Apple 공식
문서가 정반대다.

> Don't use this API to create new apps; instead, create new apps on the App Store Connect website.

`apps` 리소스는 **이미 있는 앱을 읽고 고치는 용도**다. 따라서 요청서가 말한 비대칭이 존재하지
않고, **양쪽 다 웹 콘솔이 유일한 길**이라 플랫폼을 나눌 이유가 사라졌다 — 한 스킬로 묶었다.

진짜 비대칭은 생성 **이후**에 있었다.

```
Android   패키지명 영구 · 이름/언어는 콘솔에서 변경
iOS       생성만 웹 · 번들 ID·기본 언어까지 API 로 변경 가능(Modify an app)
```

### 되돌릴 수 없는 것은 하나뿐이다

Play Console 문서로 확인했다. 요청자가 "확인하지 못했으니 추정을 적지 말아 달라" 고 한 둘이
여기 있다.

| 값 | 변경 | 근거 |
|---|---|---|
| **패키지명 · 번들 ID** | **불가** | "고유하고 영구적… 삭제하거나 다시 사용할 수 없습니다" |
| 기본 언어 | 가능 | "이는 나중에 변경할 수 있습니다" |
| 스토어 앱 이름 | 가능 | 같은 문장 |
| 앱/게임 구분 | 가능 | 같은 문장 |

**넷에 같은 무게를 실으면 정작 중요한 한 줄이 묻힌다.**

### 입력은 읽어서 제안하고 사람이 확인한다

백지에서 물으면 사람이 레포와 다른 값을 적어 넣고, 그 불일치는 업로드에서야 드러난다.
다만 **기본 언어는 코드가 정하지 못한다** — 조직 소재지와 소스 언어가 서로 다른 근거를 준다.

### 자동화 경계

```
한다        레코드 생성(승인 후) · 읽기(이름 중복·기존 레코드) · 생성 결과 검증
하지 않는다  앱 삭제 · 패키지명 변경 시도 · 가격/배포 국가 확정
            프로덕션 출시 · **로그인**
```

로그인 화면이 뜨면 `HANDOFF_REQUIRED=store_console_session` 으로 멈춘다. 자격증명을 입력하지
않는다. 정책·수출 법규 선언은 **법적 선언**이라 사람이 체크한다.

검증에서 **404 와 403 을 구별한다** — 403 은 레코드가 있다는 증거이지 없다는 증거가 아니다.

## 초안의 추출이 두 번 틀렸다 — 돌려 봐서 잡았다

zen-koi 레포로 실행하니 **그럴듯한 오답**이 나왔다.

```
앱 이름   禅鲤              values-zh 의 번역본을 집음 (기본 로케일 아님)
번들 ID   ...zenkoi.tests   순서에 따라 테스트 타깃을 집음
```

**빈 값보다 그럴듯한 오답이 더 위험하다** — 사람이 확인 화면에서 그냥 넘긴다. 기본 로케일만
읽고, 번들 ID 는 앱 타깃의 것이 다른 ID 들의 접두사라는 성질(가장 짧은 것)로 고른다.

## iphone-release 의 단정을 정정했다

"이름·기본 언어·번들 ID 가 한 번 정해지면 바꾸기 어렵다" 고 적혀 있었는데 **확인하지 않은
단정**이었다. ASC 는 셋 다 고칠 수 있다. 정정 주석을 그 자리에 남겼다.

## 통지 게이트가 이 릴리스를 막았다

v1.20.0 에 넣은 게이트가 새 마커를 잡고 릴리스를 중단시켰다.

```
[추가] 토큰   HANDOFF_ACCESS=browser · HANDOFF_CLEARED=app_record
             HANDOFF_DECISION=app_record · HANDOFF_REQUIRED=store_console_session
[추가] 헤더   ## 🏷️ 앱 레코드 생성 결과 — <slug>
❌ 통지가 필요합니다 — 릴리스를 중단합니다.
```

#30 에서 "사람이 기억해야 하는 절차는 또 빠진다" 고 적고 게이트를 만들었는데, **다음 릴리스에서
바로 걸렸다.** 게이트가 없었으면 이 다섯도 v1.18.0 처럼 조용히 나갔다. 통지 후 `NOTIFIED=1` 로
진행했다.

`HANDOFF_CLEARED` 는 이번이 **스킬에서의 첫 실사용**이다.

## 검증되지 않은 것

**이 스킬은 아직 한 번도 실제 스토어 레코드를 만들지 않았다.** 추출 게이트만 실측했다. 브라우저
생성 절차·로그인 부재 처리·§7 검증은 전부 미검증이다. 첫 검증은 zen-koi 가 맡기로 했고,
되돌릴 수 없는 작업이라 그쪽도 사용자 승인을 받고 진행한다.

`app_record` 값이 `HANDOFF_REQUIRED` · `HANDOFF_DECISION` · `HANDOFF_CLEARED` 셋에 공유된다.
같은 대상의 상태 전이라 의도한 설계지만, **값만 보고 grep 하면 셋이 구별되지 않는다.**
소비자는 마커 이름까지 포함해 grep 해야 한다(이슈 #35 에 명시).
