## 무엇을 고쳤나 — 게이트가 "검사 못 함" 을 통과로 취급했다

v1.14.0 의 §6-1 은 다음 두 경우를 구별하지 못했다.

```
grep 이 실행되지 못함(경로가 틀림 · 글롭이 셸에서 전개됨)   → 종료 코드 1
위반이 없음(정상)                                           → 종료 코드 1
```

`if grep ...; then 실패; fi` 형태는 둘을 같게 본다. v1.14.0 에서 글롭을 인용해 원인 하나는
막았지만, **대상 파일이 0개면 인용해도 똑같이 조용히 통과한다.**

게이트가 위반을 놓치는 쪽이라 **실패처럼 보이지 않는다.** debug 빌드에 실 광고 ID 가 들어가면
무효 트래픽으로 AdMob 계정이 정지될 수 있는데, 게이트가 통과를 보고하는 상태였다.

## 조치

대상 파일 수를 먼저 세고 0개면 그 자체를 실패로 삼는다. 종료 코드는 이 레포의 E2E 규약(0/1/2)을 따른다.

| 코드 | 뜻 |
|---|---|
| 0 | 통과 — 검사를 수행했고 위반이 없다 |
| 1 | 위반 — debug 에 실 ID, 또는 release 에 테스트 ID |
| 2 | **검사 못 함** — 대상 파일 0개. 통과가 아니다 |

**`2` 를 통과로 취급하지 않는다.** 호출하는 쪽이 `rc != 0` 으로 판정해야 한다.

게이트를 앵커 블록(`app-ads:id-gate`)으로 만들어 테스트가 문서의 코드를 직접 실행하게 했다.
`setup:*` 앵커들과 같은 방식이다 — **실행 코드는 검증 가능해야 한다.**

## 검증

- `aiops/tests/app-ads-id-gate.test.sh` 15건 신규 → **전체 499건 통과**
- **bash·zsh 양쪽에서 돌린다.** 글롭 전개 차이가 원래 버그의 원인이었다
- `G5` 는 검사불가·통과·위반의 종료 코드가 **서로 다름을 직접 검사**한다

### 변이 테스트에서 테스트 자신의 결함이 나왔다

신규 15건이 처음부터 전부 통과했으나, 일부러 코드를 망가뜨려 테스트가 실제로 잡는지 확인했다.

| 변이 | 실패 건수 |
|---|---|
| 글롭 인용 제거 | 4 |
| 0개 검사 제거 | 8 |

이때 **`G7`("글롭이 모두 인용됨")이 인용을 제거했는데도 통과했다.** 정규식이 틀려 헛돌고 있었다.
`-name` 뒤 토큰을 뽑아 `*` 를 포함한 것이 인용으로 시작하는지 보는 방식으로 고쳤다.

이번 릴리스가 고치는 결함과 **같은 종류**다 — 검사가 실제로 수행되는지 확인하지 않으면 통과는
아무것도 보장하지 않는다.

## 영향 범위

`/aiops:app-ads` §6-1 만 고쳤다. **이 원칙은 다른 게이트에도 해당하지만 이번 릴리스에서 다루지
않았다** — 기존 게이트들이 같은 패턴을 쓰는지는 확인하지 않았다.

## 역호환

**통과(0)로 잘못 보고되던 경우**다.
